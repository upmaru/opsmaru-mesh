# Project instructions

Use the pinned mise Elixir/OTP and Node/OpenSpec tools. opsmaru-mesh is a pure Elixir library (`:opsmaru_mesh`) providing the control plane for cross-node networking between Incus hosts registered in central Opsmaru. Keep it a library: no application callback, process, listener, repository, credentials, timer or backend connection may start merely because a host loads or starts the dependency. The host (central Opsmaru) supplies Incus connections, node records, allocations, policies and tenant identity explicitly on every call and persists whatever the library returns.

Opsmaru is the control plane only. Traffic flows directly between nodes and never through Opsmaru or this library. An existing mesh must keep forwarding on its last applied configuration when the control plane is unavailable. Talk to Incus only through `opsmaru_incus`: never invoke a host CLI, SSH to a node, probe local sockets or require a host agent. Never read, store or return a node's WireGuard private key; keys are generated on the node and only public keys leave it. Never renumber, modify or delete networks, profiles or instances this library did not create, including `incusbr0` and the `default` project's existing resources.

Isolation is a security property. Default deny between Incus projects, never widen access as a side effect of a failed or partial apply, and treat any change that can join two projects' traffic as requiring explicit spec coverage and review. Do not call the mesh "zero trust" in code, docs or releases until identity-bound policy is actually implemented and verified.

Use OpenSpec for substantial behavior changes and validate planning before implementation. Distinguish pure unit evidence, fixture evidence against recorded Incus responses, and explicit real-Incus acceptance. Real-backend acceptance requires explicit opt-in, an isolated project and private credentials; never run tests against production data or commit ignored `_build`, `deps`, `.integration`, secrets or acceptance state. Run `mise trust` and `mise install` for the checkout; the canonical check is `mise run check`.

Use Git Flow: main is released history, develop is integration, feature/* starts from develop, release/* starts from develop and finishes into both branches, and hotfix/* starts from main and finishes into both. Publish development work on its feature branch. Hex is the only distribution route for the package. Do not finish/merge branches, create release tags or publish packages without user authorization.

Every pull request opened by a bot or automated agent must be created as a draft (for example, `gh pr create --draft`) and remain a draft until a human marks it ready for review. Bots and agents must never mark any pull request ready for review, including after checks pass or when asked to prepare it for review. Only a human may perform that transition. If an agent mistakenly opens a non-draft pull request, it must convert that pull request back to draft; a later human decision to mark it ready must be respected.
